# 2.1 Command search and key commands

Screenshots: `app-command-search.png` (Ctrl+K with "me" typed),
`app-menu-keys.png` (the Edit menu showing each command's keys),
`app-key-commands.png` (Settings → Key commands), and
`app-key-commands-press.png` and `app-key-commands-clash.png` (adding K
to Loop, which the metronome already has).

- [ ] **2.1 Command search.** Press Ctrl+K anywhere, even while typing in
      the lesson notes. Type "metro" and press Enter. Then try other
      words: "click", "save", "bundle", "render", "shortcuts". Use Up
      and Down to pick a row, Esc to close it. Pass: the command you
      meant is at or near the top, Enter runs it, letters typed into the
      search never run their own commands (R doesn't start recording),
      and Esc closes it without running anything.
- [ ] **2.1 Changing a key.** Settings → Key commands. Type "loop" in its
      search, press Add key and then F6: F6 now loops. Press Add key
      again and then K: it asks whether to move K from the metronome.
      Try Move it and Leave it. Remove a key with its ✕, press Reset on
      the row, then Reset all. Close and reopen the app. Pass: each
      change works straight away, the menus and hover texts show the new
      keys, and the keys are the same after reopening. Tab, Enter, the
      arrow keys and F2 are refused with a note.
- [ ] **2.1 The default keys.** Use the app for a while with the keys as
      they come, Ctrl+K included. Say which ones you would change, and
      if any clash with your keyboard or Windows (Ctrl+K and Alt with
      the arrows are the likeliest).

## Decisions to accept

- [ ] **Which keys can't be changed.** Built: Tab, Enter, the arrow keys
      (with any of Ctrl, Alt and Shift) and F2 stay fixed, because they
      move around and edit whatever has the keyboard. Esc stops waiting
      for a key, so it can't be given by pressing it (Reset gives it
      back to Clear the selection). Everything in the menus can be
      changed.
- [ ] **Keys must match exactly.** Built: a key with Shift held is a
      different key, so Shift+Space no longer plays and Shift+S no longer
      splits (they did before, by accident). Holding a key down runs it
      once, except Undo and Redo, which repeat.
- [ ] **Keys belong to the computer, not the project.** Built: they are
      kept in `keys.txt` beside the device settings, so your teacher's
      keys don't change yours when you share a project.
