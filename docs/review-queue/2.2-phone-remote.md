# 2.2 Phone remote

Needs an Android phone (Android 8 or newer) on the same Wi-Fi as the
test PC. Nothing here has run on a phone yet: the app was built without
one, so expect the first run to turn something up, and say what.

## On the PC and phone

- [ ] **Install the app.** Open the latest green **ci** run on `main`,
      download the `daw-remote-android` artifact, unzip it and copy
      `app-debug.apk` to the phone (or open it from the phone's
      browser via a share). Android asks to allow installs from that
      source, because the build is not signed for a store. Pass: the
      "DAW Remote" app opens to a "Pair with the desktop" screen.
- [ ] **Pair.** On the PC, Settings → Phone remote… → Show a code to
      pair a phone (screenshot `app-phone-remote.png`). In the app,
      Scan the code and point the camera at it; allow the camera when
      asked. Pass: the app shows the project's name, the PC's name and
      "connected" at the top, the PC's window lists the phone under
      "Connected now" and "Paired phones", and the code disappears.
      If the camera doesn't read the code, type the text under it into
      the app instead and say so.
- [ ] **Transport from the stool.** Open a project with a couple of
      tracks. On the phone: Play, Stop, Start, the Count-in and Click
      toggles, and the Loop toggle. Pass: each does what the PC's own
      control does, the PC's window follows, the phone's position
      counter runs with the PC's, and a press buzzes.
- [ ] **Record and undo.** Give a track an input on the PC. On the
      phone, press Arm on that track (it goes red on both), then
      Record, then Play; play something; Stop. Pass: a take appears on
      the PC's timeline. Press Undo last take: the take disappears;
      Edit → Undo on the PC brings it back.
- [ ] **Meters.** With a track armed, hit a drum or talk into the mic.
      Pass: that track's bars on the phone move with the PC's meter,
      and a very loud hit shows CLIP for a moment.
- [ ] **Overview.** Tap in the overview at about bar 5, then drag.
      Pass: the playhead on the PC moves with it, landing on bar lines
      (and on a marker's bar when near one), and recording starts from
      there. Markers show by name; the loop range shows when Loop is
      on; armed tracks have a red edge; takes are green, files blue,
      older takes dim.
- [ ] **Sideways and upright.** Turn the phone. Pass: sideways, the
      buttons sit beside the overview and tracks; upright, above them.
      Nothing is cut off on your phone's screen.
- [ ] **Screen stays on.** Leave the app open past the phone's screen
      timeout. Pass: it stays on. Switch to another app: the screen
      turns off as usual.
- [ ] **A lost phone never spoils a take.** Start recording from the
      phone, then turn the phone's Wi-Fi off mid-take. Pass: the PC
      carries on recording; Stop on the PC keeps the take. Turn Wi-Fi
      back on: the app shows "looking for the desktop…" then
      "connected" by itself, without scanning again.
- [ ] **Restart both.** Close and reopen the PC app and the phone app.
      Pass: the phone reconnects on its own (the PC listens whenever a
      phone is paired). If the PC's network address has changed, it
      won't: Pair again on the phone, Show a code on the PC.
- [ ] **Forget.** On the PC, Forget the phone. Pass: the phone drops
      off and goes back to the pairing screen with the desktop's reason;
      scanning a new code pairs it again.

## Decisions to accept

- [ ] **Local network only, no discovery.** The code holds the PC's
      address, so the phone finds it without scanning the network. If
      the PC's address changes (a new router, say), the phone needs a
      new code. Say if finding the PC by itself matters enough to add.
- [ ] **A sideloaded debug build, for now.** It is unsigned and
      installs from the CI artifact. The choices for later are a signed
      package attached to our releases, or a store listing (which costs
      a registration and a review). Say which, when it matters.
- [ ] **Which phone, and does the camera read the code.** Note the
      phone model and Android version in this file so later changes
      can be checked against it.
