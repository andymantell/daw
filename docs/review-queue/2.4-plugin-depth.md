# 2.4 Plugin depth: side buses, delay changes, scaling, older versions, checks

Same `daw.exe`. Everything here was built and tested in the cloud with the
project's own test plugin, which now has a third effect, "DAW Test
Router", with a sidechain input, an extra output and a delay that
changes. Screenshots from the cloud:
`/mnt/project-files/screenshots/app-plugin-sidechain-outputs.png` (an
effect listening to another track, with its extra output ticked and the
line shown when a newer version stands in) and `app-plugin-check.png`
(Settings → Plugins with Check plugins and the window cap). None of it has been tried with real plugins or on Windows yet;
the plugin window scaling in particular could only be compiled, not
run, in the cloud.

## On the PC

- [ ] **2.4 Check your plugins.** Settings → Plugins → **Check plugins**.
      Each plugin is loaded in a process of its own, played a second of
      sound in usual and odd block sizes, has its settings saved and
      loaded into a second copy, and has its sidechain input and extra
      outputs tried where it has them. Pass: it finishes, the line says
      where the report went, and **Copy report** copies it. Paste the
      report into a reply (or into `docs/plugin-compatibility.md`) and
      I'll fill in the public list. A "no" says what went wrong; it may
      be a fault of ours, so send those especially. The same report can
      be made without opening the app: `daw.exe --check-plugins
      report.md`.
- [ ] **2.4 A plugin listening to another track.** Put a plugin
      compressor that has a sidechain input (most do) on a backing track,
      and in the effects window pick your guitar track under **Listen**.
      Pass: the backing ducks when you play, as the built-in compressor
      does. Some plugins also need their own "external sidechain" or "key
      input" switch turned on in their window. If a plugin with a
      sidechain shows no Listen picker, say which.
- [ ] **2.4 A plugin's extra outputs.** For an effect with more than one
      output (a splitter, or a reverb with a separate early/late output,
      say), its row in the effects window shows **Also hear:** with a box
      per extra output. Pass: ticking one mixes it in, unticking takes it
      out, and both survive saving and reopening.
- [ ] **2.4 A delay that changes while playing.** Some plugins change
      their delay when you switch a setting (a "look-ahead" or "high
      quality" mode on a limiter or amp sim). Play, and flip it. Pass:
      the sound drops out for a moment at most, the delay shown in the
      effects window changes, and the track stays in time with the
      others afterwards.
- [ ] **2.4 Plugin windows at your display's scale.** With Windows set to
      a scale above 100 % (Settings → Display), open a plugin's window
      with **Edit**. Pass: it is the right size, not tiny. Plugins that
      can draw themselves at any scale should be sharp; ones that can't
      are stretched by Windows and may look a little soft. With two
      displays at different scales, drag the window across: it should
      resize to suit. This is the part I could not run in the cloud.
- [ ] **2.4 A cap on open plugin windows.** Settings → Plugins → **Plugin
      windows open at once**: set 2, then open three plugin windows.
      Pass: the first one closes and the status line says so. Set back
      to "no limit" if you'd rather not have it.
- [ ] **2.4 A newer version opening an older one's project.** Only if it
      happens: when a plugin you use is updated to a new major version
      that installs as a separate plugin, open a project saved with the
      old one after removing the old one. Pass: the effect opens with the
      new version, its settings as they were, and a line under it says
      it stands in for the older version. This only works where the
      plugin says it can (VST 3 lets plugins declare it); otherwise the
      effect shows as not installed, as before.

## Decisions to accept

- [ ] **2.4 Silence while a plugin restarts.** When a plugin running in
      the app changes its delay, VST 3 asks the host to stop and start
      it. While that happens (a few milliseconds, typically) the track
      is silent rather than playing the unprocessed sound. Say if you'd
      rather hear the dry sound for that moment.
- [ ] **2.4 Extra outputs mix into the track.** A plugin's extra outputs
      can be heard in its own track only, for now. Sending each to a
      track of its own (as you would a drum instrument's outputs) waits
      for instrument tracks, since that is mostly where it matters.
- [ ] **2.4 Automation of plugin settings, next.** Plugin setting lanes
      are still moved from the window thread, so exports don't follow
      them yet. The follow-up is for the engine to hand each plugin its
      setting changes block by block (VST 3 takes them with each block,
      down to the sample), in the app and in the helper process alike.
- [ ] **2.4 No cap by default.** Plugin windows are not capped unless you
      set one.
