# 2.9 Panes and windows of their own

Screenshots: `app-panes.png` (the timeline and mixer, with the comments
beside), `app-panes-lesson.png` (layout 3, "Lesson", from Ctrl+3),
`app-panes-drag.png` and `app-panes-dropped.png` (the mixer's tab dragged
to the right of the timeline), `app-pane-menu.png` (a pane's ⋯ menu),
`app-pane-full-size.png`, `app-view-menu.png`, `app-save-layout.png`,
`app-panes-windows-on.png` and `app-pane-own-window.png`. In the cloud the
small icons on each pane's header show as boxes, as on other screenshots;
the own-window shot is drawn inside the main window there, where on a PC
it is a real window.

- [ ] **2.9 Moving panes.** Drag the Mixer tab over the timeline: a blue
      area shows where it will go (left, right, above, below, or a tab in
      the middle). Drop it, then drag it back below. Do the same from the
      ⋯ menu (Move it), without the mouse: Tab to ⋯ and press Enter.
      Drag the gap between two panes to resize them. Pass: each drop
      lands where the blue area said, nothing gets lost, and the panes
      feel quick to rearrange.
- [ ] **2.9 Collapse, full size, close.** On a pane's header try ▾
      (collapse to its header), ⛶ (full size; Ctrl+Shift+F does the same
      for the pane last clicked in) and ✕. Open closed panes from the View
      menu. Pass: the timeline can't be closed; everything else comes back
      where it was before.
- [ ] **2.9 Layouts.** Press Ctrl+1, Ctrl+2 and Ctrl+3 (Recording,
      Mixing, Lesson). Arrange something of your own, then View → Save
      layout…, name it, and recall it with its key. Restart the app.
      Pass: the layout you left is there after the restart, and your own
      layout is in the View menu, the command search (Ctrl+K, type its
      name) and Settings → Key commands.
- [ ] **2.9 Windows of their own, on your PC.** View → Panes in their own
      windows. On the mixer's header press ⧉: it opens in its own window.
      Drag that window to a second screen, then save a layout. Close the
      window with its own close button. Pass: the mixer goes back into
      the main window (it never closes the project), and recalling the
      layout puts it on the second screen again. Keys (Space, Ctrl+K)
      work while that window has the focus.
- [ ] **2.9 A missing screen.** With a pane on the second screen, quit,
      turn that screen off or unplug it, and start the app. Then plug it
      back in. Pass: the window opens on the main screen, then goes back
      to the second screen within a few seconds of it returning. Also
      check that the pane's window looks sharp on a screen with
      different scaling (125% against 100%, say).
- [ ] **2.9 Screen reader in a pane's own window.** With a screen reader
      running, Tab around a pane in its own window. Pass: its controls
      are read out as they are in the main window.
- [ ] **2.9 Speed with windows open.** With the mixer and tuner in
      windows of their own and the song playing, open Settings →
      Performance check. Pass: no more DSP load or dropouts than with
      them in the main window. (Each window is redrawn with the main one,
      which is simple but costs more drawing; see below.)

## Decisions to accept

- [ ] **Windows of their own are off by default.** Built: one window
      until you turn on View → Panes in their own windows. Turning it off
      brings every pane back in, and a saved layout with windows opens
      their panes in the main window, with a note.
- [ ] **Which panes there are.** Built: the timeline, mixer, comments,
      lesson notes and tuner. The tuner and lesson notes were floating
      windows and are panes now. Dialogs (export, devices, key commands
      and the like) and the track effects window stay as they were.
      Plugin editors are not panes yet: moving one between windows means
      moving the plugin's own native window, which is untested on every
      system.
- [ ] **Where a pane opens.** Built: the mixer below the timeline;
      comments, notes and tuner to the right of it, each below the last
      one open, so all can be seen. The Lesson layout tabs the notes with
      the comments instead.
- [ ] **Layouts belong to the computer.** Built: kept in `layout.txt`
      beside the device settings, never in the project. Nine layouts at
      most, one per key Ctrl+1 to Ctrl+9 (changeable in Key commands).
      Not built yet: the project remembering which panes were open, which
      the roadmap mentions. Say if you want it; a shared project would
      then open the same panes for your teacher.
- [ ] **How a pane's window is drawn.** Built: each window is drawn along
      with the main one, every frame. That is simple and safe, and fine
      for a few windows; if the speed check above shows a cost, the
      windows can be moved to drawing on their own.
- [ ] **Finding screens.** Built for Windows only: the app asks Windows
      which screens there are, every two seconds while a pane has its own
      window. On macOS and Linux it puts windows where they were and
      leaves the rest to the system.
