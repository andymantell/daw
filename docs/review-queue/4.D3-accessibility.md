# 4.D3 Accessibility across the whole app

Built while the owner was away (Phase 4 plan item D3). The timeline's
screen-reader and keyboard work (1.9) now reaches the other panes:

- **Values in words.** A slider used to tell a screen reader only its
  number: a pan of 0.3, a frequency on a log scale, a volume with no
  "dB". Now the mixer (volume, pan, sends, control groups, master),
  the monitor section, every built-in effect's settings, plugin
  parameters, instrument settings, layers, the browser's preview level
  and the click level say their value as shown: "30% left", "-6.0 dB",
  "4.0:1", "12 ms".
- **Names in words.** The effect chain's ▲ ▼ ✖ buttons are read as
  "Move EQ up", "Move EQ down" and "Remove EQ". A test opens every
  pane full size, and the effects and instrument windows, and fails if
  any control has no name or only a symbol, or a slider has no value in
  words. A new pane is checked the same way before it merges
  (docs/AI_ASSISTANTS.md says how).
- **Notes by keyboard.** In the note editor each note is reached with
  Tab and read as "C4 at bar 1 beat 2, 1 beat long, velocity 100".
  Left and Right move it a grid step, Up and Down a semitone (Shift: an
  octave), Enter selects it, Delete removes it. Clicking a note gives it
  the keyboard.
- **Automation lanes by keyboard.** Each lane is reached with Tab and
  read as its points: "Volume lane: -20.0 dB at bar 1, rising to -6.0 dB
  at bar 3". Up and Down raise or lower it at the playhead (adding a
  point there), Enter puts a point at the playhead as it is.
- **Hearing values.** Help → Hear the value (Ctrl+Shift+H) plays the
  value of the control with the keyboard, or the one last dragged: a
  pan as a tone from that side, a level as a tone that loud, any other
  setting as a tone as high as it sits in its range, and an automation
  lane as a tone that rises and falls with it over a second and a half.
  Its words show for a few seconds at the bottom left, marked so a
  screen reader reads them out. Assistants do the same with
  `hear_value`.
- **Fixed places.** The Play button keeps its width as it turns into
  Stop, and the clock keeps room as it counts, so the transport bar no
  longer shifts while playing. A test checks the transport and mixer
  controls stay put through arming, muting, soloing, adding effects,
  looping and playing.

## To try

- [ ] **D3 Narrator on the mixer.** Turn on Narrator (Ctrl+Win+Enter),
      open the mixer and Tab to a track's pan and volume, then press the
      arrow keys. Pass: Narrator reads the value as "30% left" or
      "-6.0 dB", not a bare number. This is the part least certain: the
      words are given to the screen reader as the slider's value text,
      and whether Narrator prefers that to the number has not been
      checked on Windows. Say what it reads.
- [ ] **D3 Effects panel.** Open a track's effects, add a compressor,
      and Tab through its settings with Narrator on. Pass: each is read
      with its name and value in its unit, and the order buttons as
      "Move Compressor up" and so on.
- [ ] **D3 Notes by keyboard.** Open the note editor on a clip, click a
      note, then use the arrows, Shift+Up, Enter and Delete. Pass: the
      note moves, changes pitch, is selected and is removed, and Narrator
      reads the new note after each key (Tab away and back if it
      doesn't).
- [ ] **D3 Automation by keyboard.** Draw a volume lane with two points,
      Tab to the lane in the automation pane, press Ctrl+Shift+H, then
      Up a few times. Pass: you hear a tone that rises as the lane does,
      Narrator reads the lane's points, and Up raises it at the
      playhead.
- [ ] **D3 Hearing a pan and a level.** Tab to a pan slider set left
      and press Ctrl+Shift+H; then a fader. Pass: the tone comes from
      the left, and a lower fader is quieter. Say if the tones are too
      loud or too long (pan and level 0.4 s, lanes 1.5 s).
- [ ] **D3 A screen-reader user.** If one can be found, ask them to
      record a take and set a mix with the keyboard alone. Their view is
      the real test of this.

## Not built

- Whether the value words reach Narrator (see above) is untested on a
  real screen reader; the tests read the accessibility tree egui gives
  it.
- Notation lanes and windows, the step sequencer's steps and the
  lessons pane were checked for names (they pass) but their drawn
  contents (staves, steps) are not read one by one yet.
- Number boxes that count things (bars, steps, hits) are read as plain
  numbers; only sliders say a unit.
- With most controls focused, only key commands marked for typing run
  (Hear the value is one); Space, R and the rest wait until the focus
  leaves. That is how it was before; say if Space should play from a
  focused slider too.
